# 🦜 초롱이 — 시니어를 위한 실시간 아바타 말동무

어르신이 앵무새 캐릭터 **초롱이**와 목소리 또는 글로 대화하는 웹 서비스입니다.
초롱이는 대화 내용의 감정을 읽어 **표정과 몸짓을 바꾸고**, 실제 목소리 파형에 맞춰 **입(부리)을 움직입니다.**

---

## 1. 설치

```bash
npm install
```

## 2. API 키 넣기

`.env` 파일은 이미 만들어져 있습니다. 메모장으로 열어 키만 붙여 넣으면 됩니다.

```bash
notepad .env
```

파일 안에서 이 줄을 찾아

```
OPENAI_API_KEY=
```

`=` 바로 뒤에 키를 붙여 넣고 저장(Ctrl+S)하세요.

```
OPENAI_API_KEY=sk-proj-여기에본인키
```

- 따옴표(`" "`)를 붙이지 마세요
- `=` 앞뒤에 띄어쓰기를 넣지 마세요
- **`#` 으로 시작하는 줄(설명 줄)에는 넣지 마세요** — 그 줄은 서버가 읽지 않습니다
- 키는 <https://platform.openai.com/api-keys> 에서 발급하며, **만든 직후 한 번만** 보여 줍니다

제대로 들어갔는지는 서버를 켤 때 나오는 `✅ API 키 확인 완료` 문구로 알 수 있습니다.
키가 없으면 웹 화면 맨 위에도 노란 안내 막대가 뜹니다.

> 키는 서버에서만 읽습니다. 브라우저로는 절대 전달되지 않으며, 모든 OpenAI 호출은 서버가 대신합니다.
> `.env`는 `.gitignore`에 등록되어 있어 깃에 올라가지 않습니다.

## 3. 실행

```bash
npm start
```

브라우저에서 <http://localhost:3000> 을 엽니다.

> 음성으로 말하려면 **크롬 또는 엣지**를 권장합니다(브라우저 실시간 음성인식 사용).
> 다른 브라우저에서는 녹음 후 서버가 받아쓰는 방식으로 자동 전환됩니다.

## 두 가지 이야기 — 시작 화면에서 고릅니다

초롱이는 성격이 다른 두 대화를 갖고 있습니다. 규칙도 화면도 다르므로 섞지 않고 갈라 두었습니다.
처음 들어오면 둘 중 무엇을 할지만 고르시면 됩니다. **말동무(아바타)는 여기서 고르지 않습니다** —
들어가서 [친구 바꾸기] 로 언제든 바꾸실 수 있습니다.

| | 건강관리 이야기 (`/health.html`) | 사진 보며 옛이야기 (`/recall.html`) |
| --- | --- | --- |
| 무엇을 하나 | 오늘 기분과 몸을 살피고, 스스로 정하신 것을 이어 가게 돕습니다 | 사진 한 장을 보며 그때의 기억을 편하게 이야기합니다 |
| 대화 규칙 | 초롱이 말동무 규칙 + 오늘 돌봄 (Bloom 논문 반영) | 팀에서 받은 회상 프롬프트 `prompts/recall-system.txt` 전체 |
| 화면에 있는 것 | 오늘 기분 · 오늘의 활동 · 오늘 기록, 아플 때 · 약 카드 | 사진, 다른 사진 · 그만 보기, 기억으로 남기기 |
| 함께 있는 것 | 아바타, [인지치료], [지난 이야기] 서랍, [친구 바꾸기] | 〃 |

**지난 이야기 서랍** — 들어오면 늘 새 대화입니다. 왼쪽 위 [지난 이야기] 를 누르면 그동안 나눈
대화가 최근 것부터 나오고, 고르시면 그 이야기가 화면에 그대로 다시 그려집니다.
두 챗봇은 서랍을 따로 씁니다. 대화가 한 마디도 오가지 않으면 목록에 남기지 않습니다.

**인지치료** — 두 화면 어디서나 [인지치료] 를 누르면 오늘의 활동 하나가 나옵니다.
회상 · 숫자 · 날짜 · 사진 네 가지 가운데 오늘 아직 안 하신 것을 고릅니다. 다 하셨으면 더 시키지 않습니다.
날짜 활동은 맞히게 하지 않고 **먼저 알려 드린 뒤 함께 말해 봅니다.**

**부르는 말** — 초롱이는 상대를 '어르신'이라고 부르지 않습니다. 그렇게 불리는 것이 불편하신 분도
계시기 때문입니다. 부르는 말 없이 이야기하고, 이름을 알려 주시면 그 이름으로 부릅니다.

## 시니어를 위한 화면 설계

디자인은 장식을 걷어낸 **차분하고 단정한 방향**입니다.
얇은 테두리(1px), 절제된 색(짙은 초록 하나만 강조색), 넉넉한 여백, 선으로 그린 아이콘을 씁니다.
글씨 크기와 대비는 크게 유지하되 알록달록한 요소는 쓰지 않습니다.

- **글자 크기 3단계** (보통 / 크게 / 아주 크게) — 선택하면 다음에도 유지됩니다
- **모든 버튼 높이 40px 이상**, 마이크·보내기 버튼은 54px
- **주고받은 이야기** — 소리가 잘 안 들려도 오간 말이 옆에 글자로 남습니다
  (아바타 아래 자막은 접었습니다. 같은 말을 두 번 보여 드릴 까닭이 없고, 그 자리는 아바타가 씁니다)
- **설정 한 곳에** — 글자 크기 · 천천히 대화 · 캐릭터 바꾸기는 [설정] 안에 모았습니다.
  화면에는 자주 쓰는 것만 둡니다
- **소리 끄기** — 조용한 곳에서는 글자로만
- **다시 들려주세요** — 방금 한 말을 반복
- 상태를 색과 글자로 함께 안내 (듣고 있어요 / 생각하고 있어요 / 말하고 있어요)

## 설정 바꾸기 (.env)

| 항목 | 기본값 | 설명 |
| --- | --- | --- |
| `CHAT_MODEL` | `gpt-4o` | 대화 모델 |
| `TTS_MODEL` | `gpt-4o-mini-tts` | 목소리 모델. 사용할 수 없는 계정이면 `tts-1`로 자동 대체됩니다 |
| `TTS_VOICE` | `nova` | 목소리 종류. `nova`(밝고 또랑또랑), `shimmer`(맑고 앳됨), `coral`(따뜻함) |
| `VOICE_PITCH` | `1.16` | 음높이. 1은 원래 목소리, 1.2는 아주 높은 아이 목소리 (최대 1.35) |
| `STT_MODEL` | `whisper-1` | 받아쓰기 모델 |
| `PORT` | `3000` | 서버 포트 |
| `ACCESS_CODE` | (없음) | 설정하면 이 암호를 아는 사람만 접속할 수 있습니다 |
| `DATA_DIR` | `./data` | 사진과 기억이 저장될 폴더 |
| `KEEP_TRANSCRIPT` | `true` | `false` 면 대화 원문을 남기지 않습니다 (지표는 그대로) |
| `PHOTO_VISION` | `true` | 대화할 때 올리신 사진을 모델에게도 보여 줍니다 |
| `PHOTO_ANALYSIS` | `PHOTO_VISION` 을 따름 | 사진을 올릴 때 모델이 한 번 살펴 추천 점수에 씁니다 |
| `ANALYSIS_DETAIL` | `high` | 살펴볼 때 얼마나 자세히 볼지. 사람 수를 세야 해서 `high` |

## 회상 대화

사진을 보며 옛 기억을 이야기하시도록 돕는 기능입니다 (`/recall.html`).

**대화 규칙은 팀에서 받은 `prompts/recall-system.txt` 를 그대로 씁니다.** 코드 안에 옮겨 적지
않습니다 — 옮겨 적으면 팀이 프롬프트를 고칠 때마다 두 곳이 어긋납니다. 함께 받은 `app.py` 는
터미널용 프로토타입이라 대화 상태를 프로그램이 들고 있었는데, 초롱이 서버는 차례마다 화면이 보내
주는 대화 기록으로만 돌아가므로 **그 상태를 기록에서 다시 셉니다** (`lib/recall-prompt.js`).

| 프롬프트가 정한 것 | 코드가 지키는 방법 |
| --- | --- |
| 한 번에 두 문장까지 | 길어지면 첫 문장과 마지막 문장만 남깁니다 (`limitToTwo`) |
| 질문은 하나까지 | 넘는 질문 문장을 걷어냅니다 |
| 사진 한 장에 질문 다섯 번까지 | 첫 고정 질문부터 세고, 다 쓰면 정리하고 고르시게 합니다 |
| 잇달아 두 번 물었으면 쉬기 | 다음 차례는 '반영 + 구체적인 이야기 초대' 로 씁니다 |
| 사진이 바뀌면 처음부터 | 화면이 첫 고정 질문을 다시 드리므로 저절로 초기화됩니다 |
| 그만하고 싶다고 하시면 | 모델에게 묻지 않고 정해진 인사로 마칩니다 |

**이야기를 넓히는 차례는 회의 피드백(2026-09-16)을 따릅니다** (`lib/recall-flow.js`).
기억이 떠오르시면 **사람 → 장소 → 사건 · 행동 → 감각 → 감정 → 의미** 로 넓히되, 이미 말씀하신
단계는 건너뜁니다. "딸이랑 제주도 바다에 갔을 때야" 라고 하시면 누구와 어디는 다시 묻지 않고
바로 그날 있었던 일부터 여쭙습니다.

기억이 안 나신다고 하시면 갈래가 완전히 달라집니다. **사진에 남은 찍은 날 → 사진 속 사람 →
장소 → 사물 · 행동 → 쉬운 선택형** 순으로 단서를 하나씩만 건넵니다.

찍은 날을 맨 앞에 두는 것은, 그것이 시스템이 이미 아는 사실이라 지어낸 말이 아니고
한 해 · 한 달만 짚어 드리므로 맞히게 하는 물음도 아니기 때문입니다.
("괜찮아요, 바로 떠오르지 않아도 돼요. 이 사진은 1998년에 찍은 사진인데, 그때 있었던 일이 떠오르시나요?")
인화된 옛 사진을 휴대폰으로 다시 찍은 것으로 보이면 파일 날짜는 '오늘' 이라 쓰지 않고,
보호자나 어르신이 적어 두신 해만 씁니다.

사람과 장소 칸에서는 **적어 두신 내용이 있으면 그것을 먼저** 쓰고 누가 적었는지 밝힙니다
("보호자분이 함께한 분을 '딸, 사위'라고 적어 두셨어요."). 적어 둔 것이 없으면 사진에서
보이는 것으로 채웁니다.

**단서는 코드가 정한 문장 그대로 나갑니다.** 모델에게 맡겨 보았더니 문장을 줄이다 단서를
통째로 빠뜨리거나("그때 있었던 일이 떠오르시나요?" 만 남음) "~것으로 보입니다" 처럼 바꿔
말했습니다. 단서가 나가는 곳도 사다리 한 곳뿐입니다 — 두 곳에서 나가자 순서가 뒤엉켰습니다.

답이 정해져 있으므로 **단서를 건네는 차례에는 모델을 부르지 않습니다.** 기다림도 값도 줄고,
모델이 문장을 바꿔 말할 여지도 없습니다. ("그만할래" 도 같습니다)
("여기는 설악산이네요" 가 아니라 "산과 정상 표지석이 보이네요") 그래도 떠오르지 않으시면
더 캐묻지 않고 사진을 바꾸거나 쉬실지 고르시게 합니다.

**마칠 때는 오늘 떠올린 기억을 정해진 꼴로 정리해 드립니다.** 단계별로 떠올리신 것 ·
이번에 잘 안 떠오른 것 · 여쭙지 않은 것을 가르고, 여쭙지 않은 단계는 아예 적지 않습니다.
실제로 하신 말씀만 옮기고, 잘했다 못했다 평가하지 않습니다. 저장은 직접 고르십니다
(**[추억 저장하기] [저장하지 않기]**).

| 어르신 상태 | 초롱이 반응 | 질문 |
| --- | --- | --- |
| 위험 · 응급 표현 | `SAFETY_FLOW` 안전 안내 | 안 함 |
| 아직 이야기 이어가는 중 | `BACKCHANNEL` 맞장구 + 질문지 질문 | **하나** |
| 감정을 직접 말씀하심 | `VALIDATE_EMOTION` 함께 느끼며 받기 + 질문지 질문 | **하나** |
| 새 사건 · 사람 · 장소 | `REFLECT_CONTENT` 반응 + 질문지 질문 | **하나** |
| 한 이야기가 마무리됨 | `SUMMARIZE` 짧게 정리 + 질문지 질문 | **하나** |
| 말씀이 멈춤 | `FOLLOW_UP` 새 이야깃거리 + 질문지 질문 | **하나** |
| 그만하고 싶다고 하심 | 정해진 마무리 인사 뒤 사진을 접고 끝냄 | 안 함 |
| 불편 · 피로 | `OFFER_CHOICE` 선택 제공 | 선택만 |

**질문 예산은 코드가 강제합니다.** 프롬프트로만 부탁하면 모델이 결국 질문을
덧붙이기 때문입니다. `server.js` 의 `questionBudget()` 이 지난 이력을 세어
이번 차례에 물어도 되는지 정하고, 대답이 온 뒤 `limitQuestions()` 가
규칙을 어긴 질문 문장을 걷어냅니다.

- 한 번에 질문은 하나까지이고, 질문만 달랑 하지 않습니다 (질문뿐인 답에는 반응 한마디를 앞에 붙입니다).
- **사진 회상은 사진 한 장에 다섯 번까지** 묻고, 잇달아 두 번 물었으면 다음 차례는 쉽니다
  (팀 프롬프트의 숫자입니다 — `lib/recall-prompt.js`). 건강관리 대화는 최근 여섯 번 말하는 동안
  네 개까지, 연달아 묻지 않습니다.
- 다만 **종료 선택과 안전 안내의 물음은 걷어내지 않습니다.**
  여기서 자르면 어르신이 대화를 그만둘 길이 막힙니다.

**없는 사실을 말하지 않게** 프롬프트에는 `verified_fields` 에 있는 항목만
들어갑니다. 화면은 `memory_id` 만 보내고 내용은 서버가 직접 찾습니다.
어르신이 새로 말씀하신 내용은 확인 전까지 `UNVERIFIED` 주장으로만 쌓입니다.

### 사진 올리기 — 대화 중에 바로

대화 화면 아래 **+ 사진** 을 누르면 사진을 고를 수 있습니다. 끌어다 놓거나
붙여넣어도 됩니다. 고르시면

1. 대화 기록에 사진이 뜨고, 초롱이 옆에 사진이 크게 걸립니다.
2. 사진 파일에서 **찍은 날과 위치**를 자동으로 읽어 저장합니다.
3. **"이 사진은 나에게 얼마나 중요한 사진인가요?"** 를 여쭙습니다.
   ★ 평범한 사진 · ★★ 소중한 사진 · ★★★ 매우 소중한 사진 · 이 사진으로 이야기하고 싶지 않아요
4. 고르시면 등록이 끝납니다. 사진을 보며 나누는 이야기는 아래 **기억 회상 지원** 을
   누르시면 점수가 높은 사진부터 시작합니다.
   "이야기하고 싶지 않아요" 를 고르시면 사진은 넣어 두고 추천에서만 뺍니다.

미리 등록해 둘 필요가 없습니다. `POST /api/memories/upload` 한 번에 사진 검사와
기억 만들기가 끝납니다. 사진이 아닌 파일은 기억을 만들기 전에 걸러내므로
빈 기억이 남지 않습니다.

### 초롱이가 사진을 본다 (PHOTO_VISION)

사진을 모델에게도 함께 보냅니다. 사진에 보이는 장면 · 물건 · 음식 · 날씨는 대화 거리로
자연스럽게 꺼냅니다. 사진을 올릴 때 살펴 둔 결과(장소 · 하는 일 · 보이는 것 · 사람 수)도
이야깃거리로 함께 넘기고, 이미 대화에 나온 것은 빼고 넘깁니다 (`photoMaterial`).

다만 **사진만 보고 알 수 없는 것은 말하지 않습니다.**

| | |
| --- | --- |
| 말해도 되는 것 | 장면, 물건, 계절, 날씨, 분위기 |
| 말하지 않는 것 | 누구인지("따님이시군요"), 나이, 관계, 연도, 지명, 사진 속 글씨 |
| 겉모습 평가 | 하지 않습니다 |

그게 딸인지 며느리인지 이웃인지 사진만 보고는 알 수 없고, 틀리면 어르신은
초롱이가 제 가족도 못 알아본다고 느끼십니다. 그래서 어르신이 말씀해 주실
때까지 "옆에 계신 분" 처럼 부릅니다. 어르신 말씀이 사진에서 보이는 것과
달라도 바로잡지 않습니다.

`PHOTO_VISION=false` 로 끄면 사진은 화면에만 뜨고 모델은 보지 않습니다.
살펴 둔 결과가 있으면 그것만 이야깃거리로 씁니다.

### 사진 등록 — 보호자가 미리

`/memories.html` 에서 보호자가 사진과 생애정보를 등록합니다.
등록한 항목만 `verified_fields` 에 들어가고, 빈 칸은 대화에 쓰이지 않습니다.
제목 · 함께한 사람 · 장소를 적어 두면, 초롱이가 사진에서 본 것에 더해
그 사실까지 알고 이야기합니다.

등록 순서는 대화 화면과 같습니다 — **사진 고르기 → 찍은 날 · 위치 자동 저장 →
중요도 고르기 → 등록**. 찍은 해를 아시면 함께 적어 주세요.

### 어느 사진부터 보여 드릴까 — 사진 추천 점수

사진이 여러 장이면 점수가 높은 사진부터 보여 드립니다. **별점이 곧 순서가 되지는
않습니다.** 소중한 사진이라도 이야기의 실마리가 없으면 말문이 잘 트이지 않고,
같은 사진이 되풀이되면 금세 지루해지시기 때문입니다. 아래를 모두 더합니다.

| 항목 | 어떻게 아나 | 점수 |
| --- | --- | --- |
| ① 어르신이 고르신 중요도 | 사진을 올릴 때 직접 고르심 | ★ +10 · ★★ +20 · ★★★ +30 |
| ② 회상 단서가 풍부한 사진 | 사람 · 사물 · 장소 · 활동이 많을수록 | 최대 +20 |
| ③ 사람이 있는 사진 | 사진 살펴보기 | +15 |
| ④ 무엇을 하는 장면인지 보이는 사진 | 사진 살펴보기 (식사 · 여행 · 졸업식 …) | +15 |
| ⑤ 어디인지 알 수 있는 사진 | 사진 살펴보기 (집 · 학교 · 일터 · 여행지 …) | +10 |
| ⑥ 열 살에서 서른 살 무렵의 사진 | 태어나신 해와 찍은 해 | +10 |
| ⑦ 최근 세 번 동안 나오지 않은 사진 | 회기 기록 | +10 |
| ⑧ 최근 세 번 중 두 번 이상 나온 사진 | 회기 기록 | −20 |
| ⑨ 이야기하고 싶지 않다 · 힘들어하심 · 감춤 | 직접 고르심 · 대화 중 표시 · 보호자 | 추천 제외 |

**② 는 많을수록 오릅니다.** 사람(세 명까지) · 사물(네 개까지) · 장소 · 활동을 단서로
세어, 여섯 개면 만점입니다. 표의 예시인 "가족 + 음식 + 바다 + 테이블" 이 만점에
닿습니다. 한 종류가 독차지하지 않게 사람 열 명을 단서 열 개로 치지는 않습니다.

**사진 살펴보기 (②~⑤)** — 사진을 올리면 모델(gpt-4o)이 한 번 살펴 사람 수 · 사물 ·
장소 · 활동 · 시기를 스키마로 못박아 돌려줍니다 (`lib/photo-analyzer.js`).
올리신 분을 기다리게 하지 않으려고 응답을 먼저 보내고 뒤에서 합니다. 사람이 누구인지 ·
나이 · 관계는 알아보지 않습니다. 살펴본 결과는 **순서를 정하는 데만** 쓰고 대화
프롬프트에는 넣지 않습니다. 확인된 사실이 아니기 때문입니다.

**찍은 해 (⑥)** 는 이 순서로 씁니다.

1. 보호자나 어르신이 직접 적은 해
2. 사진 파일의 날짜 — 인화된 옛 사진을 휴대폰으로 다시 찍은 것으로 보이면
   파일 날짜가 '오늘' 이라 쓰지 않습니다
3. 사진을 보고 짐작한 시기 (1970년대 처럼 십 년 단위. 범위가 절정기와 겹치면 인정)

태어나신 해는 `/memories.html` 맨 위에 적습니다. 모르면 ⑥ 은 0점입니다.

**되풀이 막기** — **기억 회상 지원** 은 올리신 사진만 씁니다. 최근에 되풀이된 사진은
점수가 깎인 채로 줄에 섭니다. (API 를 `kind` 없이 부르면, 되풀이된 사진밖에 없을 때
이야깃거리로 한 번 쉬어 갑니다. 사진이 한 장뿐이면 점수를 깎아도 늘 그 사진이 나오기 때문입니다.)

**찍은 날과 위치** — 화면에서 사진을 줄이면 파일 정보가 떨어져 나가므로 줄이기 전에
원본에서 읽습니다 (`public/exif.js`). 위치는 소수 넷째 자리(약 11미터)까지만 서버에
남기고, 화면으로는 "위치 정보 있음" 만 보냅니다. 모델에게는 보내지 않습니다.
사진 파일 자체에는 위치가 남지 않습니다 (줄이면서 떨어져 나감).

`/memories.html` 의 **추천 순서** 에서 사진마다 점수가 항목별로 보이고, 별점 ·
이야기하고 싶지 않음 · 찍은 해를 바로 고칠 수 있습니다. 숫자는 `lib/photo-score.js`
맨 위 `WEIGHTS` 에서 바꿉니다. 화면의 점수표도 거기서 그대로 가져와 어긋나지 않습니다.

| API | 하는 일 |
| --- | --- |
| `GET /api/memories/next?kind=PHOTO` | 기억 회상 지원 — 올리신 사진 중 점수가 가장 높은 것 (없으면 null) |
| `GET /api/memories/scores` | 추천 순서 · 항목별 점수 · 다음에 보여 드릴 사진 |
| `PATCH /api/memories/:id` | 중요도 · 이야기하고 싶지 않음 · 찍은 해 · 감춤 바꾸기 |
| `POST /api/memories/:id/analyze` | 사진 다시 살펴보기 (실패했거나 이 기능 전에 올린 사진) |
| `GET · PUT /api/profile` | 태어나신 해 |

### 이야깃거리 (API 에만 남아 있습니다)

> 대화 화면의 **기억 회상 지원** 은 올리신 사진만 씁니다. 아래 이야깃거리는
> `GET /api/memories/next` 를 `kind` 없이 부를 때만 쓰입니다.

보호자가 사진을 올리기 전에도 첫날부터 회상 대화를 할 수 있게, 이야깃거리
열일곱 개를 미리 넣어 두었습니다 (`lib/themes.js`). 실제 회상 프로그램도
대부분 사진보다 주제로 진행하고, 사진은 그 주제를 도와주는 단서로 씁니다.

- 열 살에서 서른 살 무렵의 기억이 가장 또렷하게 떠오르므로 학창 시절, 첫 일,
  첫 월급, 혼례, 아이 키우던 때를 두텁게 넣었습니다.
- 지금 계절과 맞는 주제를 앞으로 당깁니다. 김장철에 김장 이야기를 꺼내면
  "올해도 해야 하는데" 하면서 말문이 트입니다.
- 어르신 개인의 사진이 늘 이야깃거리보다 먼저 나옵니다. 남의 이야깃거리보다
  내 사진이 훨씬 잘 떠오릅니다. (최근에 되풀이된 사진밖에 없을 때만 이야깃거리로
  한 번 쉬어 갑니다.)

### 힘들어하시면 다음부터 꺼내지 않습니다

슬픔과 불편은 다릅니다. 회상하다 눈물을 보이시는 것은 자연스럽고 오히려 마음이
풀리는 과정이라, 그걸 이유로 감추면 그리운 이야기를 나눌 길이 막힙니다.

| | 표시 |
| --- | --- |
| "보기 싫어", "치워라", "묻지 마", 화를 내심 | **표시함** — 자동 선택에서 뺌 |
| 눈물을 보이시며 계속 말씀하심, "그립다", 돌아가신 분 이야기 | 표시하지 않음 |
| 그냥 피곤하다고 하심 | 표시하지 않음 (쉬시게 함) |

표시해도 지우지는 않습니다. 왜 힘들어하셨는지는 사람이 알아야 하고, 다시 열지도
보호자가 판단할 일입니다. `/memories.html` 에 흐리게 표시되고 몇 건인지 알려 줍니다.

### 보호자가 보는 회상 기록

`/memories.html` 아래쪽에 어르신이 무슨 이야기를 하셨는지 나옵니다. 회상 도구의
값어치는 앱 안에서 끝나지 않고 그 다음 가족과의 대화에 있습니다. 무슨 이야기를
하셨는지 알면 만나셨을 때 그 이야기를 이어 나누게 됩니다.

초롱이가 한 말은 빼고 어르신이 하신 말씀만 보여 줍니다.
`KEEP_TRANSCRIPT=false` 면 말씀 대신 몇 마디 나누셨는지만 나옵니다.

### 기억 회상 지원

대화 화면 아래 **기억 회상 지원** 을 누르면 시작합니다. 사진에 대해 정답을 맞히게 하거나
기억을 시험하는 대화가 아닙니다. 사진을 단서로 어르신이 자신의 경험을 떠올려
이야기하시도록 돕는 대화입니다.

**① 사진으로 회상 단서 제공 → ② 열린 질문 → ③ 경청 · 반영 → ④ 필요할 때만 추가 질문이나 단서
→ ⑤ 기억을 강요하거나 정정하지 않기**

1. 올리신 사진 중 **추천 점수가 가장 높은 사진** 한 장을 띄웁니다.
   이야깃거리(사진 없는 주제)로는 넘어가지 않습니다. 사진이 없으면 올려 달라고 말씀드립니다.
2. 첫 말은 사진을 살펴본 결과로 보이는 것을 한두 가지 짚은 뒤, 어떤 사진이든 늘 같은 물음으로 엽니다.
   — "바닷가에서 찍은 사진이네요. 수박이랑 양산도 보이네요. **이 사진을 보면 어떤 기억이 떠오르세요?**"
   살펴본 결과가 없으면 물음만 드립니다 (`public/recall-opening.js`).
3. 그다음은 친구끼리 이야기하듯 주고받습니다. 어르신 말씀에 반갑게 반응하고, 어울리면 사진 속
   장면 · 물건으로 한마디 보탠 뒤, **질문지 질문 하나로 이야기를 이어 갑니다.**
4. 질문지(`lib/recall-questions.js` — 팀 질문지의 여덟 영역 서른다섯 질문)에서 지금 이야기와 사진에
   맞는 질문을 무작위로 셋 골라 건네고, 초롱이는 그 가운데 가장 어울리는 하나를 그대로 여쭙니다.
   질문지의 '언제 사용하면 좋은지' 도 따릅니다 — 동행자가 아직 안 나왔으면 "이때 누구와 함께 계셨어요?",
   바닷가 · 공원 같은 야외 사진이면 날씨 · 소리, 꽃 · 음식 · 바다가 보이면 냄새 · 향, 대화 후반에는 개인적 의미.
   같은 사진 이야기에서 한 번 여쭌 질문은 다시 하지 않고, 공감만 하고 질문이 없으면 코드가 하나를 붙입니다.
   질문지에 없는 "언제 · 몇 · 누구 · 어디" 질문은 하지 않습니다.
5. "기억이 안 나요" 하시면 괜찮다고 안심시켜 드리고 단서를 **한 가지만** 건넵니다.
   보호자가 적어 둔 내용이나 어르신이 전에 들려주신 내용이 있으면 그중 하나를,
   없으면 사진에 보이는 것 하나를. 누가 적었는지 그대로 밝힙니다.
   그래도 모르시면 다른 사진을 볼지 여쭙습니다.
6. 적어 둔 내용과 다르게 말씀하셔도 바로잡지 않습니다.
7. "다른 사진 보자" 하시면 화면이 다음 사진으로 넘어갑니다.
   "그만할래", "이제 됐어" 처럼 그만하고 싶다고 하시면 모델에게 묻지 않고 곧바로
   **"네, 오늘 이야기는 여기서 마칠게요. 함께 이야기해 주셔서 감사합니다."**
   로 인사한 뒤 사진을 접고 대화를 마칩니다. 이 문장은 팀 프롬프트(19번)가 정한 것입니다.
   마치면서 **오늘 떠올린 기억**을 정리해 보여 드리고 저장할지 여쭙습니다.
   (사진이 싫다는 말은 따로 봅니다 — 아래)
   초롱이가 "다른 사진을 볼까요?" 하고 여쭙기만 한 때에는 화면이 움직이지 않고, "응" 하셔야 넘어갑니다.
   **다른 사진 · 그만 보기** 버튼도 같습니다. 넘기거나 접을 때 오늘 새로 들은 이야기를
   기억으로 남길지 여쭙습니다.

오늘 이야기를 마치고 싶다는 말("그만할래")과 사진을 물리치는 말("이 사진은 보기 싫어, 치워")은
다르게 봅니다. 앞의 것으로는 그 사진이 추천에서 빠지지 않습니다.

대화 규칙에는 여섯 가지 원칙을 넣었습니다 — 열린 질문 · 개인화된 단서 · 사진 활용 ·
되받아주기 · 기억을 정정하지 않기 · 어르신을 자신의 경험에 대한 전문가로 대하기.
상태 표에는 **기억이 안 남(CANNOT_RECALL → OFFER_CUE)** 과
**그만하고 싶음 · 다른 사진(WANTS_CHANGE)** 이 새로 들어갔습니다.

#### 원칙을 코드로 지키는 것

프롬프트로만 부탁하면 모델이 버릇처럼 어깁니다. 실제 대화로 확인한 것들이라
`lib/reply-rules.js` 에서 답을 한 번 더 다듬습니다.

| 모델이 버릇처럼 하는 것 | 코드가 하는 일 |
| --- | --- |
| 한 번에 질문 여러 개 · 질문 예산 넘기기 | 넘는 질문 문장을 뺍니다 |
| 질문만 달랑 한 답 | 모델이 따로 보낸 반응 한마디(`reflection`)를 앞에 붙입니다 |
| 정답이 있는 물음 ("꽃은 언제부터 키우기 시작하셨어요?") | 언제 · 몇 · 누구 · 어디 로 묻는 질문 문장을 뺍니다 |
| 함께한 사람 짐작 ("친구분들과 함께 하셨나 봐요") | 어르신이 말씀하지 않은 사람을 짐작한 문장을 뺍니다 |
| 물음표만 뺀 질문 ("어떤 일이 있었는지 궁금하네요") | 질문하면 안 되는 차례에는 뺍니다 |
| "그랬지 뭐", "응" 에 이야기를 잇지 않고 넘어가기 | 멈추신 말을 코드가 알아보고, 여쭙지 않았으면 아직 여쭙지 않은 열린 질문 하나를 붙입니다 |
| 공감만 하고 대화가 멈춤 (사용 피드백) | 이야기하시는 차례에 질문지 질문이 없으면, 지어낸 질문을 빼고 질문지 질문 하나를 붙입니다 |
| 그만하자는 말에 이야기를 더 이어 가기 | "그만할래 · 이제 됐어 · 그만 볼래 · 쉬고 싶어" 는 코드가 먼저 알아보고 정해진 마무리 인사로 끝냅니다 |
| "다른 사진을 볼까요?" 하고 대답을 듣기 전에 사진 넘기기 | 여쭙는 답에는 화면이 움직이지 않습니다 |
| 기억이 안 난다는 말에 적어 둔 내용을 전부 늘어놓기 | 이번에 건넬 단서 **한 가지만** 모델에게 보여 줍니다 |
| 보호자가 적은 것을 어르신이 하신 말처럼 건네기 ("…모습이라고 하셨어요") | 건넬 문장을 정해 주고("보호자분이 장소를 '강릉 바닷가'라고 적어 두셨어요."), 누가 적었는지 밝히지 않은 단서 문장은 그 문장으로 바꿉니다 |
| 단서를 건네며 "다른 사진을 볼까요?" 까지 한 번에 · 그래도 모르시는데 단서를 또 건네기 | 처음 기억이 안 난다고 하실 때는 넘어가자는 말을 빼고 떠올리실 틈을 드립니다. 다시 모르신다고 하시면 단서는 빼고 넘어갈지만 여쭙니다 |

되받으며 누가 한 일인지를 바꾸는 것(따님이 주운 조개를 "주워 오셨군요")은 코드로 가려내기 어려워
프롬프트로만 막습니다.

어르신 기분을 부드럽게 헤아리는 말("재미있으셨겠어요")은 예전에는 코드로 걷어냈습니다.
그런데 걷어내면 "그러셨군요." 만 남고, 정해진 공감 문장으로 바꾸면 같은 말만 되풀이되어
어느 쪽이든 대화가 딱딱해졌습니다. 이제는 그대로 두고, 단정하거나 슬픈 이야기에 좋은 기분을
붙이는 것만 프롬프트로 막습니다.

첫 말도 모델에게 맡기지 않고 화면이 정해진 틀로 만듭니다. 맡기면 첫 말부터 사람이나 때를
짐작하는 말이 섞이기 쉽습니다.

### 새로 들은 이야기는 확인 뒤에 저장합니다

음성인식이 잘못 알아듣거나 모델이 잘못 새겨들은 내용이 사실로 굳으면, 다음
대화부터 초롱이가 그 틀린 이야기를 사실처럼 말하게 됩니다. 그래서 대화 중
나온 새 내용은 곧바로 저장하지 않습니다.

- 대화 중 나온 새 이야기는 `UNVERIFIED` 주장으로만 쌓입니다. 프롬프트에
  들어가지 않으므로 초롱이가 아직 사실처럼 말하지 않습니다.
- 회기가 끝날 때 어르신께 보여 드리고 여쭙습니다.
- **남기겠다** 하시면 `VERIFIED` 가 되어 다음 대화부터 쓰입니다.
- **아니요** 하셔도 지우지 않고 `UNVERIFIED` 로 그냥 둡니다.
  지워 버리면 나중에 보호자가 살펴볼 길이 없어집니다.
- 여쭙는 것은 **이번 회기에 들은 것만** 입니다. 지난번에 답을 못 받은 이야기까지
  한꺼번에 물으면 오늘 하지도 않은 말을 왜 묻느냐가 되고, 서로 어긋나는 값이
  나란히 확정될 수 있습니다.

대화 기록은 `SESSION` 으로 따로 남습니다. `/api/sessions/metrics` 로 질문 대비
되짚기 비율, 연속 질문 횟수 같은 지표를 볼 수 있습니다.

## 어디가 아프다고 하실 때

"병원에 가 보세요" 한마디로 넘기지 않습니다. 급한 정도에 따라 셋으로 나눠 대합니다.

| 단계 | 신호 | 초롱이가 하는 일 |
| --- | --- | --- |
| 응급 | 가슴 통증 · 숨참 · 쓰러짐 · 말이 어눌함 · 한쪽 팔다리에 힘이 없음 · 갑작스런 심한 두통 | 다른 말 없이 **119** 안내 |
| 오늘내일 진료 | 열이 계속 · 점점 심해짐 · 아파서 잠을 못 잠 · 다친 뒤 붓고 못 디딤 · 며칠째 안 나음 | 공감 뒤 오늘 중 병원 권유, 가족 연락 돕기 |
| 흔한 불편 | 무릎 시큰함 · 허리 뻐근함 · 소화 불편 · 가벼운 두통 | 공감 + 편해질 만한 것 한두 가지 + 병원에 가셔야 할 때 |

말씀드려도 되는 것은 **누구에게나 안전한 생활 속 이야기**뿐입니다.
무리하지 마시고 쉬시라는 말, 따뜻하게 하시라는 말(다치신 직후라면 차게),
물 자주 드시라는 말, 천천히 일어나시라는 말 같은 것들입니다.

절대 하지 않는 것 — 병명 짐작, 약 이름이나 용량, 복용량 조절, 낫는다는 약속,
병원에 안 가셔도 된다는 말, 민간요법이나 건강식품 권유.

아플 때는 상태를 여쭤도 됩니다. "언제부터 그러셨어요?"는 기억력 검사가 아니라
걱정에서 나오는 물음이라 회상 질문 예산에 넣지 않습니다. 다만 한 번에 하나만
여쭙고, 이때만 백오십 자까지 씁니다.

돈, 계좌, 비밀번호 같은 개인정보는 묻지 않습니다.
돈·계좌·비밀번호 같은 개인정보는 묻지 않습니다.

## 목소리를 아이 목소리로 만드는 방법

OpenAI 음성 합성에는 음높이 조절 기능이 없습니다. 그래서 이렇게 우회합니다.

1. 서버가 `VOICE_PITCH` 배만큼 **느리게** 음성을 만들도록 요청합니다
2. 응답 헤더 `X-Voice-Pitch` 로 그 값을 브라우저에 알려 줍니다
3. 브라우저가 그 배속으로 **빠르게** 재생합니다

말 속도는 원래대로 돌아오고 **음높이만 올라가서** 어린아이 목소리가 됩니다.
너무 높다고 느끼시면 `.env` 의 `VOICE_PITCH` 를 `1.10` 정도로 낮추세요.

## 캐릭터 세 명

| 캐릭터 | 성격 | 목소리 |
| --- | --- | --- |
| **초롱이** | 다정한 앵무새. 아이처럼 밝게 재잘거립니다 | `nova` + 음높이 1.16 |
| **준호** | 손주 같은 이십 대 청년. 씩씩하고 살갑습니다 | `ash` (청년 남성) |
| **서연** | 손녀 같은 이십 대 청년. 상냥하고 세심합니다 | `coral` + 음높이 1.04 |

화면 위 **친구 바꾸기** 버튼으로 언제든 바꿀 수 있고, 선택은 브라우저에 저장됩니다.
목소리는 서버에서만 정하므로 브라우저가 임의의 목소리를 요청할 수 없습니다.

세 캐릭터는 부위 이름(`ch-eye-l`, `ch-beak-lower` …)을 똑같이 쓰고,
좌표 차이만 `geom` 에 따로 적어 두어 감정·립싱크 코드를 그대로 공유합니다.

## 캐릭터에 대해

초롱이의 겉모습은 납작한 벡터 그림체(둥근 사각형 몸, 큰 흰자 눈, 작은 노란 부리)를 따르되,
앵무새다운 볏과 갈고리 부리, 색깔 날개 끝으로 초롱이만의 생김새를 갖도록 그렸습니다.
다른 회사의 마스코트를 그대로 옮기지 않았으므로 실제 서비스에 그대로 쓰셔도 됩니다.

## 아바타 손보기

`public/avatar.js` 안에서

- `C` — 색상표 (몸 색, 부리 색 등)
- `SVG` — 초롱이의 생김새. 부위마다 `id`가 있어 각각 움직입니다
- `EMOTIONS` — 감정별 표정 수치 (눈썹 각도, 눈꺼풀, 볏 기울기, 볼, 눈물 등)

표정을 바꾼 뒤 <http://localhost:3000/expressions.html> 에서 한 번에 확인할 수 있습니다.
